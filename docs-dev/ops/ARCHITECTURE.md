# 이 앱은 어떻게 굴러가나 — 운영진용

> **읽는 사람**: 행정팀·PM. 코드를 안 읽어도 되게 썼습니다.
> 컬럼 하나하나의 정의는 [`SHEET-SCHEMA.md`](../spec/SHEET-SCHEMA.md) 에 있습니다.
> 이 문서는 **"무엇을 바꾸면 무엇이 따라 바뀌는가"** 만 다룹니다.

---

## 1. 시트가 곧 데이터베이스입니다

```
 ┌───────────────┐      ┌──────────────┐      ┌─────────────────┐
 │  참가자 휴대폰  │ ───▶ │  GAS 웹앱     │ ───▶ │  구글 스프레드시트 │
 │  (웹 화면)     │ ◀─── │  (중간 다리)   │ ◀─── │  ★ 원장 ★       │
 └───────────────┘      └──────────────┘      └─────────────────┘
                               │
                               └──▶ Google Drive (사진 원본)
```

**앱은 시트를 보여 주는 창일 뿐, 원장이 아닙니다.**

실질적인 의미는 이렇습니다.

- 앱에 안 보이는 값이 있으면 **시트를 먼저 보세요.** 시트가 맞습니다.
- 앱이 통째로 죽어도 **데이터는 시트에 그대로** 있습니다.
- 시트를 직접 고치면 앱에 반영됩니다. **별도의 "앱 관리자 화면"에서 다시 입력할 필요가 없습니다.**
- 반대로, **시트를 잘못 고치면 앱이 바로 틀어집니다.** 되돌리는 안전장치가 없습니다.
  (구글 시트의 `파일 → 버전 기록`이 사실상의 되돌리기입니다. 알아 두세요.)

## 2. 탭 10개는 두 부류입니다

| 사람이 채우는 탭 | 앱이 쓰는 탭 |
|---|---|
| `Participants`(마스터) — 명단·조 배정·회비 | `Progress` — 조장이 찍은 지점 도착/완료 |
| `Config` — 설정 스위치 | `Journal` — 참가자가 올린 탐험일지 |
| `Checkpoints` — 4개 지점 정보 | `Log` — 감사 기록 (자동) |
| `Courses` — 코스별 방문 순서 | |
| `Teams` — 조 이름·색상 (선택) | |
| `Timeline` — 당일 일정표 | |
| `Notices` — 공지 | |

**오른쪽 3개는 사람이 건드리지 마세요.** 앱이 행 번호를 기준으로 갱신하므로,
중간에 행을 끼워 넣거나 지우면 엉뚱한 행이 수정됩니다.
(수정이 꼭 필요하면 값만 고치고, **행을 추가·삭제하지 마세요.**)

## 3. "조 ID" 라는 건 없습니다

조를 특정하는 것은 **`참여 일자` + `조 배정` 두 값의 조합**입니다.

> `10/31(토)` 의 **1조** 와 `11/07(토)` 의 **1조** 는 **서로 다른 조**입니다.

**행정팀이 조 ID 를 따로 관리하지 않게** 하려고 이렇게 했습니다.
명단에 날짜와 조 이름만 정확히 적으면 조는 자동으로 생깁니다.

### 부서와 일자는 별개 축입니다

운영은 **청년부 10/31, 장년부 11/07** 로 1:1 입니다. 그런데도 시스템은
`캠프 대상`(부서)과 `참여 일자`를 **끝까지 따로** 봅니다.

이유는 하나입니다 — **일부 인원이 섞일 수 있기 때문**입니다.
"청년부니까 10/31" 이라고 코드에 박아 두면, 사정상 다른 날 오는 그 한 사람이
**로그인부터 실패**하고 조 배정·갤러리까지 연쇄로 어긋납니다.
따로 두면 그냥 명단에 적힌 대로 동작합니다.

대신 **관리자 화면에는 부서 필터**가 있어 청년부/장년부를 나눠 볼 수 있습니다.
조원의 부서가 섞인 조는 `혼합` 으로 표시되며, 어느 쪽을 골라도 보입니다.

## 4. 연결 고리는 3개뿐입니다

| 고리 | 잇는 것 | 끊어지면 |
|---|---|---|
| `참가자ID` (`P0001`) | 사람 ↔ 그 사람의 일지·진행 기록 | 앱이 자동 부여. **사람이 지우면 안 됩니다** |
| `참여 일자` + `조 배정` | 사람 ↔ 조 ↔ 진행 현황 | 둘 중 하나라도 비면 **그 사람은 조가 없는 상태**가 됩니다 |
| `배정 코스` → `Courses` → `Checkpoints` | 조 ↔ 돌아야 할 지점 순서 | 아래 "함정" 참고 |

`배정 코스` 에 적은 글자가 `Courses` 탭의 코스 이름과 **글자까지 같아야** 이어집니다.

## 5. 탐험일지는 시트에 어떻게 기록되나

가장 자주 나오는 질문입니다. **사진은 시트에 들어가지 않습니다.**

```
참가자가 사진 선택
      │
      ├─ ① 휴대폰 안에서 축소   긴 변 1600px, JPEG 품질 0.8
      │                        (원본을 그대로 올리면 느리고 용량 초과가 납니다)
      │
      ├─ ② 서버가 Drive 에 저장  파일명 P0001_20261031_142530.jpg
      │                        → '링크가 있는 사람은 보기' 로 공개 설정
      │
      └─ ③ 시트 Journal 에 한 줄 추가
             사진ID  = Drive 파일 ID
             사진URL = https://drive.google.com/thumbnail?id=...&sz=w1200
```

`Journal` 한 행에 들어가는 값:

| 열 | 값 | 비고 |
|---|---|---|
| `일지ID` | `J0001` | 자동 |
| `참여 일자` / `조 배정` | 작성 시점의 값 | **스냅샷입니다** ↓ |
| `참가자ID` / `작성자명` | 작성자 | `작성자명` 도 스냅샷 |
| `지점코드` | `CP1` ~ `CP4` (없을 수도) | |
| `내용` | 소감 글 | |
| `사진ID` / `사진URL` | Drive 파일 | 사진 없으면 빈칸 |
| `상태` | `대기` → `승인` / `반려` / `삭제` | 기본 `대기` |
| `작성일시` / `수정일시` / `수정자ID` | | |
| `검토자` / `검토일시` | 관리자가 승인할 때 | |

**스냅샷이라는 뜻**: 일지를 쓴 뒤에 그 사람의 조를 바꿔도,
**이미 쓴 일지의 조는 바뀌지 않습니다.** 그 날 그 조에서 쓴 기록이기 때문입니다.
의도된 동작입니다.

**삭제는 두 단계로 다릅니다.**
- 시트의 일지 행 → `상태` 를 `삭제` 로 바꿀 뿐, **행은 남습니다**(소프트 삭제).
- Drive 의 사진 → **실제로 휴지통으로 갑니다.**

즉 **삭제된 일지의 사진은 되살릴 수 없습니다**(휴지통 보존 기간 안에는 가능).
글 내용은 시트에 남아 있으니 필요하면 `상태` 를 `승인` 으로 되돌리면 되지만,
**사진은 안 돌아옵니다.**

수정·삭제 권한은 **작성자 본인 / 그 조의 조장 / 전체 관리자** 세 부류입니다.
승인된 글을 본인·조장이 고치면 **다시 `대기` 로 내려가** 재승인이 필요합니다.
(관리자가 고칠 때는 상태가 유지됩니다.)

## 6. 바꾸면 무엇이 따라 바뀌나

| 바꾼 것 | 따라 바뀌는 것 | 언제 반영되나 |
|---|---|---|
| `Participants` 의 `조 배정` | 그 사람의 조, 조원 목록, 진행 현황 집계 | **다음 요청부터 즉시** |
| `Participants` 의 `역할` → `조장` | 그 사람이 지점 체크 버튼을 쓸 수 있게 됨 | **즉시** (재로그인 불필요) |
| `Participants` 의 `배정 코스` | 그 조가 도는 지점 **순서** | 즉시 |
| `Participants` 의 `입금 여부` | 회비 화면 표시, 관리자 집계 | 즉시 |
| `Config` 의 설정값 | 앱 전체 동작 | **최대 5분** (캐시) — 급하면 메뉴에서 캐시 비우기 |
| `Notices` / `Timeline` | 공지·일정 화면 | 최대 5분 |
| `Checkpoints` 의 위도·경도 | 지도 버튼 동작 | 최대 5분 |

**권한은 즉시, 설정은 최대 5분**이라고 외우면 됩니다.
설정을 바꿨는데 앱에 안 보이면 5분을 기다리거나,
시트 메뉴 **`캐시 비우기 (설정·공지·일정)`** 를 누르세요.

## 7. 함정 — 조용히 틀어지는 것들

에러가 안 나고 **그냥 잘못 동작**하는 것들이라 미리 알아야 합니다.

| 함정 | 증상 | 대응 |
|---|---|---|
| **`배정 코스` 오타** | 에러 없이 **기본 순서(CP1→CP4)** 로 되돌아감. "왜 우리 조만 순서가 이상하지?" | `Courses` 탭 이름과 글자까지 대조. 시트 메뉴의 **명단 점검** 이 잡아 줍니다 |
| **`참여 일자` 표기 불일치** | 그 사람이 **조에 안 잡힘**. 명단엔 있는데 조원 목록에 없음 | `Config.SESSION_1`/`SESSION_2` 값과 **글자까지** 같아야 함 (`10/31(토)`) |
| **회차는 2개 고정** | 3차를 추가해도 앱이 인식 못 함 | 회차를 늘리려면 코드 수정이 필요합니다 |
| **`Log` 탭 무한 증가** | 시트가 점점 느려짐 | 캠프가 끝나면 **오래된 행을 잘라내세요** |
| **사진 링크는 공개** | 링크를 아는 사람은 누구나 사진을 봅니다 | 초상권 민감 사진은 **승인 단계에서 거르세요**. 승인 전에는 본인·운영진만 봅니다 |
| **일지 수정용 관리자 화면 없음** | 관리자 콘솔에서 일지 **내용**은 못 고칩니다 (승인/반려만) | 내용 수정이 필요하면 **시트에서 직접** 고치세요 |
| **헤더 이름이 다름** | 그 열이 통째로 빈 값이 됨. `연락처`/`핸드폰` 이 어긋나면 **전원 로그인 실패** | 두 표기 모두 인식하게 해 뒀습니다 (D-018). 그래도 헤더를 바꿀 땐 **명단 점검**을 돌려 보세요 |
| **주민등록번호 같은 시트** | 스크립트 권한이 그 탭까지 닿음 | 앱용 시트를 분리했습니다 (D-019). 신청 폼 응답을 앱 시트로 가져오지 마세요 |
| **`MasterSync.gs` 누락** | 시트 메뉴에서 `🔄 동기화 관리` 가 **에러 없이 사라짐** | 배포 시 이 파일이 빠지지 않았는지 확인 ([`DEPLOY.md`](DEPLOY.md)) |

## 8. 당일 앱이 안 될 때

**먼저 종이로 전환하고, 나중에 시트에 직접 입력하면 완전히 복구됩니다.**
앱이 하는 일은 결국 시트에 줄을 쓰는 것뿐이기 때문입니다.

1. **확인** — 브라우저에서 `{웹앱주소}?action=health` 를 엽니다.
   `{"ok":true,...}` 가 보이면 서버는 살아 있고 문제는 다른 곳입니다.
2. **종이 전환** — 조장에게 지점별 도착/완료 시각과 점수를 **종이에 적게** 합니다.
   사진은 각자 휴대폰에 그대로 두면 됩니다.
3. **복구** — 캠프 후 `Progress` 탭에 직접 입력합니다.
   (`참여 일자` · `조 배정` · `지점코드` · `상태` · 시각)
   사진은 나중에 앱에서 올려도 되고, 안 올려도 기록은 남습니다.
4. **전면 중단이 필요하면** — `Config` 에서 `PROGRESS_OPEN` 과 `JOURNAL_OPEN` 을
   `FALSE` 로 내리면 참가자 화면에 "마감되었습니다" 가 뜹니다.
   배포 없이 즉시 적용됩니다(최대 5분, 캐시 비우면 즉시).

**절대 하지 말 것**: 장애 중에 `Progress` / `Journal` 탭의 **행을 지우는 것.**
앱이 행 번호로 갱신하므로 나중에 복구가 더 어려워집니다.
