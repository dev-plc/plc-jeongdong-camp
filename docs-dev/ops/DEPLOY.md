# 배포 가이드

`classfinder.plch.kr` 과 같은 구조입니다: **정적 프론트(GitHub Pages) + Cloudflare + GAS 백엔드**.

```
브라우저 ──HTTPS──> Cloudflare ──> GitHub Pages (docs/)   … 화면
    └────POST(text/plain)────> GAS Web App (/exec) ──> Google Sheets / Drive   … 데이터
```

---

## 1. 백엔드 (Google Apps Script)

### 1-0. 🔴 먼저 — 개인정보 정리

**앱은 현재 행정 DB(`2026 정동 가을캠프`)에 그대로 붙입니다.** 새 문서를 만들지 않습니다.

다만 신청 폼 응답 탭에 **주민등록번호**가 평문으로 있습니다. 붙이기 전에 정리하세요.

1. **주민등록번호 열 삭제** — 여행자 보험 가입이 끝났으면 **지금 지우세요.**
   아직이라면 *가입 완료 직후 삭제*를 일정에 박아 두세요.
   앱은 이 값을 쓰지 않고, 앱 스키마에 들어갈 자리도 없습니다.

   > ⚠ **두 탭에 있습니다** — `설문지 응답 시트2` **와 `응답 사본`.
   > 한쪽만 지우면 남습니다.
   >
   > 🔴 **순서를 지키세요**: `syncFormToNewDb`(📥 신규DB 동기화)가 **주민번호로
   > 생년월일·만나이를 계산**합니다. 먼저 지우면 그 값들이 빈칸으로 들어갑니다.
   > **① 신규DB 동기화 완료 → ② 주민번호 열 삭제** 순으로 하세요.
   > 이후 새로 신청하는 사람은 생년월일·만나이를 손으로 넣어야 합니다.
2. **명단(`마스터`)으로 옮길 때 주민번호·이메일은 가져오지 마세요.**
   실수로 붙여넣지 않는 한 앱 스키마에는 안 들어갑니다.
3. **시트 공유 대상 점검** — 앱 권한보다 **사람 공유 범위**가 더 현실적인 유출 경로입니다.
   누구에게 편집·보기 권한이 있는지 한 번 확인하세요.

> **권한은 코드에서 이미 좁혀 뒀습니다** (D-020). `appsscript.json` 의 스코프가
> `spreadsheets.currentonly` 라서 스크립트는 **붙어 있는 그 문서 하나만** 열 수 있습니다.
> 다른 스프레드시트는 열 수단 자체가 없습니다.
>
> 그래서 **시트를 분리할 필요가 없습니다.** (이전 버전 문서에는 분리 절차가 있었는데,
> 분리로는 권한이 막히지 않는다는 것이 확인되어 철회했습니다 — D-019 참고.)

### 1-1. 스크립트 붙여넣기

1. **행정 DB 스프레드시트**(`2026 정동 가을캠프`)를 엽니다
2. 확장 프로그램 → Apps Script

   > 🔴 반드시 **시트에서** 열어 바인딩된 스크립트로 만드세요.
   > 독립형 스크립트로 만들면 `spreadsheets.currentonly` 권한으로는 시트를 찾지 못해
   > `스프레드시트를 찾을 수 없습니다` 로 실패합니다.
3. `gas/` 안의 파일을 같은 이름으로 붙여넣기
   (`Code.gs` `Auth.gs` `Sheets.gs` `Journal.gs` `Setup.gs` `MasterSync.gs`, 그리고 `appsscript.json`)

   > 🔴 **시트에 이미 있던 동기화 스크립트는 지우고 `MasterSync.gs` 하나만 두세요.**
   > Apps Script 는 파일이 달라도 전역 스코프를 공유해서, 같은 이름의 함수가 둘이면
   > **나중에 로드된 것만 남습니다 — 에러 없이** 하나가 죽습니다.
   > 실제로 `onOpen` 과 `validateHeaders` 가 양쪽에 있었습니다.
   > `MasterSync.gs` 에 기존 기능 넷이 **전부 들어 있습니다**
   > (신규DB 동기화 · 전체 기본정보 갱신 · 헤더 검증 · 탭 간 양방향 동기화).
   >
   > ⚠ **`MasterSync.gs` 를 빠뜨리면 에러 없이 조용히** 시트 메뉴에서 `🔄 동기화 관리` 가
   > 사라집니다. `Setup.gs` 의 `onOpen` 이 이 파일의 함수를 `typeof` 로 확인한 뒤 부르기
   > 때문에, 없으면 실패하지 않고 메뉴만 안 붙습니다. 행정팀이 쓰던 마스터시트 동기화가
   > 통째로 멈추므로 붙여넣기 목록에서 빠지지 않게 하세요.
   - `appsscript.json` 이 안 보이면: 프로젝트 설정 → "`appsscript.json` 매니페스트 파일 표시" 체크
4. 저장 (▶ 실행은 아직 하지 마세요 — 아래 1-2 를 먼저)

### 1-2. 스크립트 속성 — **세팅 실행보다 먼저**

프로젝트 설정 → 스크립트 속성:

| 속성 | 값 |
|---|---|
| `ADMIN_PIN` | 운영진 공유용 PIN (6자리 이상, 숫자만 아니어도 됨) |
| `TOKEN_SECRET` | **넣지 마세요.** 첫 실행 때 자동 생성됩니다 |

> **순서가 중요합니다.** `ADMIN_PIN` 없이 다음 단계를 돌리면
> "⚠ 스크립트 속성에 ADMIN_PIN 을 추가하세요" 경고가 뜨고 결국 두 번 실행하게 됩니다.

> `ADMIN_PIN` 을 시트가 아니라 스크립트 속성에 두는 이유: 시트 편집 권한이 있는 사람 전원에게
> 노출되는 걸 막기 위해서입니다. `TOKEN_SECRET`(토큰 서명키)도 같은 이유입니다 —
> **지우면 로그인한 사람이 전부 튕깁니다.**

### 1-3. 초기 세팅 실행

함수 목록에서 **`setupSpreadsheet`** 선택 → ▶ 실행 → **권한 승인**

앱이 쓰는 탭 **9개**(`Config` `Checkpoints` `Courses` `Teams` `Timeline` `Notices`
`Progress` `Journal` `Log`)가 새로 생기고 기본값이 채워집니다.
`마스터` 탭은 **새로 만들지 않고 그대로 씁니다**(앱의 `Participants`).

> 🔴 **`마스터` 탭 맨 오른쪽에 열 두 개가 붙습니다** — `참가자ID` 와 `등록일시`.
> 앱이 사람과 기록(일지·진행 상황)을 잇는 데 필요합니다. 기존 14개 열은 그대로입니다.
> 미리 행정팀에 알려 두세요.
>
> `핸드폰`·`만나이` 는 **별칭으로 인식**하므로 `연락처`·`나이` 빈 열이 새로 생기지
> **않습니다**(D-018). 기존 탭(회비·조편성·DB참조…)도 건드리지 않습니다.

여러 번 실행해도 안전합니다 — 이미 있는 탭은 헤더만 보강하고 **데이터는 손대지 않습니다.**

> **드롭다운을 못 넣은 열이 있다고 나올 수 있습니다.** 시트에 이미 드롭다운이 걸려 있는
> 열은 구글시트가 **'열 유형'** 으로 관리해 스크립트가 덮어쓸 수 없습니다.
> 그 열만 건너뛰고 나머지는 정상 진행되며, **앱 동작에는 지장이 없습니다.**
> 기존 드롭다운을 그대로 쓰시면 됩니다.

### 1-4. Drive 폴더

1. Drive에 `정동캠프-탐험일지-사진` 폴더 생성
2. 폴더 URL의 `folders/` 뒤 문자열이 폴더 ID
3. `Config` 시트의 `DRIVE_FOLDER_ID` 에 붙여넣기

> **권한 메모**: 앱은 관리자가 직접 만든 폴더에 접근해야 하므로 `drive` 스코프를 씁니다
> (`drive.file` 은 앱이 만든 파일만 볼 수 있어 폴더 지정이 불가능합니다).
> 갤러리에서 `<img>` 로 바로 읽어야 해서 업로드된 사진은 **링크가 있는 사람은 볼 수 있음**으로
> 전환됩니다. 조직 정책으로 링크 공개가 막혀 있으면 사진은 저장되지만 썸네일이 뜨지 않습니다 —
> 그 경우 운영 계정을 개인 Google 계정으로 바꾸거나, 관리자에게 예외를 요청하세요.

### 1-5. 시트 메뉴로 초기 데이터 정리

시트로 돌아가 새로고침하면 상단에 **`🧭 정동캠프`** 와 **`🔄 동기화 관리`** 메뉴가 뜹니다.
아래 순서대로 실행하세요.

1. **`🧭 정동캠프 → 일정 변경 (회차 날짜)`** — ⚠ **지금은 필수입니다.**
   명단의 `참여 일자` 가 아직 구 일정(`10/24(토)`·`10/31(토)`)입니다.
   프롬프트에 순서대로 입력:

   | 묻는 것 | 넣을 값 |
   |---|---|
   | 1차 참여 일자 | `10/31(토)` |
   | 1차 실제 날짜 | `2026-10-31` |
   | 2차 참여 일자 | `11/07(토)` |
   | 2차 실제 날짜 | `2026-11-07` |

   미리보기에서 **바뀔 행 수**를 확인하고 진행하세요. 되돌리기는 없습니다
   (시트 `파일 → 버전 기록` 으로는 가능). 명단·조·일정표·진행·일지 다섯 탭이 함께 바뀝니다.

   > **메뉴 대신 `Config` 탭에서 직접 고쳐도 됩니다.** `SESSION_1`/`SESSION_2` 의 `값` 을
   > 바꾸면 다섯 탭이 자동으로 따라옵니다(토스트로 몇 행이 바뀌었는지 알려 줍니다).
   >
   > 🔴 **이때는 2차(`SESSION_2`)를 먼저 바꾸세요.** 새 1차 라벨(`10/31(토)`)이
   > 옛 2차 라벨과 같아서, 1차를 먼저 바꾸면 두 회차가 섞입니다.
   > 순서가 틀리면 **값을 되돌리고 안내**하니 데이터가 깨지지는 않습니다.

> **회차를 하나 더 만들려면** (사전답사 리허설 등) `🧭 정동캠프 → 회차 추가 (사전답사 등)`.
> 참여 일자 라벨과 실제 날짜를 넣으면 Config 기록 · 일정표 복사 · `참여 일자` 드롭다운 갱신까지
> 한 번에 합니다. 그 다음은 아래 2~5번 순서 그대로입니다 (D-026).

2. **`👥 명단 반영`** (`🔄 동기화 관리` 메뉴) — 설문지에만 있는 사람을 마스터에,
   마스터에만 있는 사람을 `회비`·`조편성` 같은 실무 탭에 **행째로 추가**합니다.
   **미리보기에서 누가 어디에 추가되는지 확인하고** 진행하세요.
   **`참가자ID 채우기` 보다 먼저** 돌려야 새 행에도 ID 가 붙습니다.
3. **`참가자ID 채우기`** — 명단에 `P0001` 식 ID 를 부여합니다. 로그인·일지의 기준입니다.
4. **`조 목록 동기화`** — 명단의 `(참여 일자 + 조 배정)` 조합으로 `Teams` 탭을 만듭니다.
5. **`명단 점검`** — 로그인 충돌·필수값 누락·배정 코스 오타·조장 없는 조를 찾아 줍니다.
   **여기 나온 경고를 먼저 해결하고 다음으로 넘어가세요.**

행정팀 동기화는 **`🔄 동기화 관리`** 메뉴입니다. 기존에 쓰시던 기능 그대로입니다.

| 메뉴 | 하는 일 |
|---|---|
| `👥 명단 반영 (설문지 → 마스터 → 실무 탭)` | 빠진 **행을 추가**합니다. 설문지에서는 `이름`·`핸드폰` 만 가져오고 **`캠프 대상`(부서)은 비워 둡니다** — 부서는 운영진이 정합니다. 주민번호·이메일은 가져오지 않습니다. 마스터에 없는 이름이 실무 탭에 있으면 **지우지 않고 알리기만** 합니다 |
| `📥 설문지 신규 대상자(X) 신규DB 동기화` | 설문지 응답 중 **성도여부 `X`** 인 사람만 골라 `신규DB` 탭을 다시 만듭니다. 주민번호로 **생년월일·만나이를 계산**합니다 |
| `⚡ 전체 기본정보 갱신 (DB참조 기준)` | `DB참조` 의 기본정보(성별·만나이·핸드폰·생년월일…)를 `이름` 기준으로 실무 탭 전체에 밀어넣습니다. **기본정보는 DB참조가 주인**이라 탭에서 손으로 고쳤어도 되돌아갑니다 |
| `🔍 헤더 일치 여부 검사` | 마스터·DB참조에 없는 헤더를 쓰는 탭을 **빨갛게** 표시합니다. 앱 탭 9개는 검사 대상이 아닙니다 |

이 메뉴들과 별개로, **이름을 입력하거나 값을 고치면 탭 사이에 자동으로 반영**됩니다
(`onEdit` 양방향 동기화). 마스터에서 고치든 `회비`·`조편성`에서 고치든 서로 따라갑니다.
**여러 칸을 한 번에 붙여넣어도, 빠르게 한 칸씩 쳐도 전부 반영**됩니다(D-024·D-025).
다만 한 번에 2,000칸이 넘으면 전파를 건너뛰고 토스트로 알리니, 그때는
`👥 명단 반영` 으로 맞추세요. **반영이 실패하면 반드시 토스트가 뜹니다** —
아무 말 없이 지나갔다면 반영된 것입니다.
단 **위 표의 기본정보 열은 전파하지 않습니다** — `⚡ 전체 기본정보 갱신` 과 서로 덮어쓰지
않게 하기 위해서입니다 (D-023).

> 🔴 **`📥 설문지 신규 대상자(X) 신규DB 동기화` 를 먼저 돌린 다음에**
> 주민등록번호 열을 지우세요(§1-0). 이 기능이 주민번호로 생년월일·만나이를 계산합니다.

### 1-6. 배포

배포 → 새 배포 → 유형: **웹 앱**

| 항목 | 값 |
|---|---|
| 설명 | `v1` |
| 실행 계정 | **나** |
| 액세스 권한 | **모든 사용자** |

발급된 `https://script.google.com/macros/s/.../exec` 를 복사합니다.

> ⚠ **코드를 고친 뒤에는 반드시 "배포 관리 → 편집(연필) → 버전: 새 버전 → 배포"** 를 해야
> 반영됩니다. 저장만으로는 `/exec` 이 바뀌지 않습니다. URL 은 그대로 유지됩니다.

> 🔴 **배포 뒤에는 `{API_BASE}?action=health` 를 열어 `versions` 를 보세요** (D-049).
> 파일마다 버전이 찍힙니다. 이번에 고친 파일이 새 번호가 아니면 **그 파일을 빠뜨린 것**입니다.
> `null` 이면 버전 표시가 생기기 전의 옛 파일입니다. 다시 붙여넣고 새 버전으로 배포하세요.
>
> ```json
> "versions": { "Code.gs": "v15", "Sheets.gs": "v14", … }   ← Sheets.gs 를 빠뜨렸다
> ```
>
> 각 파일 맨 위에는 **`파일이름 · 버전 · 수정일`** 과 변경 이력이 적혀 있습니다.
> 붙여넣기 전에 그 줄을 보면 새 파일인지 알 수 있습니다.

## 1-7. 읽기 미러 (Supabase) — 선택

공개 데이터(설정·지점·일정표·공지)만 Supabase 에 복제해 첫 화면을 빠르게 합니다.
**안 해도 앱은 돕니다.** 설정이 비어 있으면 지금까지처럼 GAS 로만 갑니다 (D-032).

1. **Supabase 프로젝트 생성** — 정동캠프 부서 계정(`ym@plch.or.kr`).
   GitHub 저장소 계정(`dev@plch.or.kr`)과 **달라도 무관합니다.**
   조직으로 만들고 `dev@` 를 멤버로 초대해 두세요(담당자 교체 대비).

   생성 화면에서 고를 것 — **기본을 "닫힘" 으로** 잡습니다.

   | 항목 | 값 | 이유 |
   |---|---|---|
   | **Enable Data API** | **켜기** | `/rest/v1/…`(PostgREST)가 이 설계의 **유일한 통로**입니다. 끄면 아무것도 안 됩니다 |
   | **Automatically expose new tables** | **끄기** | 2단계에서 **명단 테이블이 실수로 공개되는 것**을 막습니다. Supabase 자신도 끄기를 권합니다 |
   | **Enable automatic RLS** | **켜기** | 정책 없는 테이블은 아무도 못 읽습니다 — **안전한 실패** |
   | GitHub 연동 | **안 함** | 이 설계는 쓰지 않습니다. 권한 표면만 늘어납니다 |
   | Region | **Seoul** | 참가자가 국내, 현장 모바일 |
   | Organization | `dev@` 프로젝트가 든 조직과 **다른지 확인** | 무료 조직당 프로젝트 수 제한이 있습니다 |
   | Database password | 강한 것으로 생성 후 **보관** | 이 설계는 안 쓰지만(REST + API key 만 씁니다) 나중에 필요합니다 |

2. **테이블·정책·권한** — SQL Editor 에서:
   ```sql
   create table if not exists app_cache (
     key        text primary key,
     value      jsonb not null,
     updated_at timestamptz not null default now()
   );

   alter table app_cache enable row level security;

   -- 읽기 정책: 공개 데이터라 anon 에게 연다
   drop policy if exists "public read" on app_cache;
   create policy "public read" on app_cache for select to anon using (true);

   -- 🔴 테이블 권한. 위에서 'Automatically expose new tables' 를 껐으므로
   -- **어느 역할도 권한이 없는 상태**입니다. 읽는 쪽과 쓰는 쪽 둘 다 줘야 합니다.
   -- 정책(어떤 행을 볼 수 있나)과 권한(테이블에 닿을 수 있나)은 **별개**입니다.

   -- 읽기: 앱(브라우저)
   grant usage on schema public to anon;
   grant select on app_cache to anon;

   -- 쓰기: GAS. service_role 은 RLS 는 우회하지만 **GRANT 는 우회하지 못합니다.**
   grant usage on schema public to service_role;
   grant all    on app_cache   to service_role;

   -- ─────────────────────────────────────────────────────────────
   -- 진행 사본 (D-038). 조·지점 단위 행이라 JSONB 한 덩어리가 아닙니다.
   create table if not exists progress_cache (
     session      text not null,
     team         text not null,
     checkpoint   text not null,
     status       text not null,
     arrived_at   timestamptz,
     completed_at timestamptz,
     score        numeric,           -- 퀴즈점수가 정수가 아닐 수 있습니다
     memo         text,
     updated_at   timestamptz not null default now(),
     primary key (session, team, checkpoint),
     -- 🔴 화이트리스트의 마지막 문지기. ENUM.PROGRESS 와 같아야 합니다.
     constraint progress_status_ck check (status in ('대기','도착','완료'))
   );

   alter table progress_cache enable row level security;
   drop policy if exists "public read" on progress_cache;
   create policy "public read" on progress_cache for select to anon using (true);

   grant select on progress_cache to anon;
   grant all    on progress_cache to service_role;
   ```
   `anon` 에는 **읽기만** 줍니다. 쓰기는 GAS 의 service key 로만 합니다.

   > 🔴 **상태값을 늘릴 때의 순서**
   > 화이트리스트가 두 곳에 있습니다 — `ENUM.PROGRESS`(`gas/Sheets.gs`)와
   > 위 `progress_status_ck`. **SQL 의 `CHECK` 를 먼저 열고**, 그다음 GAS 를 고쳐
   > 재배포합니다. 거꾸로 하면 DB 가 막아서 사본만 조용히 실패합니다
   > (`Log` 탭의 `mirror.progress` 행에 남습니다).

   > 🔴 **증상별 진단**
   > - **미러 갱신이 실패한다** (`mirrorPush` 가 false) → `service_role` GRANT 누락.
   >   `Log` 탭의 `mirror.push` 행에 `permission denied for table app_cache` 가 보입니다.
   > - **앱이 미러를 안 쓴다 / 빈 화면** → `anon` GRANT 누락.
   >   이쪽은 **에러가 아니라 빈 배열**이 와서 앱이 조용히 GAS 로 폴백합니다 —
   >   겉보기엔 잘 돌아가서 원인을 찾기 어렵습니다.
3. **키 복사** — Settings → API Keys. Supabase 는 키 체계가 **둘** 입니다.

   | 탭 | 쓸 키 | 어디에 |
   |---|---|---|
   | **Publishable and secret** (권장) | `sb_publishable_…` | `config.js` 의 `SUPABASE_ANON_KEY` |
   | | `sb_secret_…` | GAS 속성 `SUPABASE_SERVICE_KEY` |
   | Legacy (anon, service_role) | `eyJhbGci…` (anon) / (service_role) | 위와 같은 자리. 둘 다 동작합니다 |

   **새 형식(`sb_…`)을 권합니다** — 화면에서 Supabase 자신이 그쪽을 권하고,
   개별 폐기·회전이 됩니다. 코드는 **두 형식 모두** 동작합니다(D-032).

   > ⚠ **`Disable JWT-based API keys` 는 누르지 마세요.** 지금 누를 이유가 없고,
   > 2단계에서 JWT 를 직접 발급할 때 영향이 있는지 먼저 확인해야 합니다.

   > 🔴 **`sb_secret_…` / `service_role` 은 `config.js` 에 절대 넣지 마세요.**
   > 저장소가 공개라 넣는 순간 전권 키가 공개됩니다. 이름이 비슷해 헷갈리는 자리입니다.

4. **GAS 스크립트 속성**: `SUPABASE_URL` · `SUPABASE_SERVICE_KEY`
   > 🔴 service key 는 **프로젝트 전권 키**입니다. 시트에서 스크립트 편집기를 열 수
   > 있는 사람은 볼 수 있습니다. 2단계(명단)로 갈 때 이 자리를 반드시 다시 봅니다.
5. **권한 재승인** — `UrlFetchApp` 을 처음 쓰므로 스코프가 늘었습니다
   (`script.external_request`·`script.scriptapp`). **새 버전 배포 후 승인 화면이 한 번 뜹니다.**
6. 메뉴 `🧭 정동캠프 → 미러 지금 갱신` 으로 한 번 밀어 보고,
   `미러 자동 갱신 켜기 (하루 1회)` 로 트리거를 겁니다.
7. **`docs/assets/js/config.js`** 에 `SUPABASE_URL` · `SUPABASE_ANON_KEY` 입력 →
   `node tools/stamp-assets.js` → 커밋.
   `SUPABASE_URL` 은 이미 넣어 두었습니다. **남은 것은 `SUPABASE_ANON_KEY` 하나**입니다 —
   Supabase → Project Settings → API Keys 의 **publishable** 키(`sb_publishable_…`)를
   **끝까지 통째로** 붙여넣습니다(화면에서 잘려 보이므로 복사 버튼을 씁니다).
   비어 있는 동안에는 미러를 **아예 호출하지 않고** 예전 GAS 경로로만 가므로 안전합니다.
   🔴 `sb_secret_…`(service_role)는 여기 넣지 않습니다 — 이 저장소는 공개입니다.
   🔴 `stamp-assets.js` 를 잊으면 브라우저가 옛 `config.js` 를 계속 씁니다(D-028).

> **끄는 법**: `config.js` 의 `SUPABASE_URL` 을 **빈 문자열로** 두면 끝입니다.
> 즉시 예전 동작(GAS)으로 돌아갑니다.

> **하루 1회 트리거는 정지 방지를 겸합니다.** 무료 프로젝트는 활동이 없으면 정지되는데,

- **일정이 또 바뀌면**: 코드가 아니라 **시트 메뉴 `일정 변경`** 으로 바꾸세요.
  `초기 세팅 실행` 을 다시 돌려도 **이미 있는 Config 값은 안 바뀝니다** (D-021).
- **설정 변경은 즉시 반영됩니다.** 시트를 고치는 순간 캐시가 자동으로 비워지고
  Supabase 사본도 함께 밀립니다 (D-022 · D-032 · D-047).
  `IMPORTRANGE` 갱신·수식 재계산처럼 사람이 직접 친 편집이 아닌 경우에만
  메뉴 `캐시 비우기 (설정·공지·일정)` 가 필요합니다.
- 🔴 **"고쳤는데 앱에 안 보인다" 면 캐시가 세 겹입니다.** 위에서부터 짚으세요 (D-047).

  | 층 | 비우는 법 |
  |---|---|
  | GAS 스크립트 캐시 | 메뉴 `캐시 비우기 (설정·공지·일정)` |
  | **Supabase 사본** | 메뉴 **`미러 지금 갱신 (Supabase)`** — 앱은 이걸 **먼저** 봅니다 |
  | 브라우저 | **탭을 닫았다 새로 열기** (5분이면 저절로 풀립니다) |

  **`Ctrl+Shift+R` 은 이 셋 중 어느 것도 비우지 않습니다.** 새로고침이 비우는 것은
  HTTP 캐시뿐이고, 브라우저 층은 `sessionStorage` 라 탭이 죽어야 사라집니다.
  시크릿 창에서만 새 화면이 보인다면 바로 이 경우입니다.
- **일지 마감**: 캠프 종료 후 `Config.JOURNAL_OPEN = FALSE` 로 작성을 닫습니다.
- **시상 발표(주일)** 전까지 `admin.html` 진행 현황 표를 그대로 화면에 띄우면 집계 자료가 됩니다.
- **장애 시**: GAS 가 멈추면 조장들은 종이 체크리스트로 전환하고, 나중에 시트에 직접 입력하면
  앱 화면이 동일하게 복구됩니다. 앱은 시트의 뷰일 뿐 원장이 아닙니다.

## 6. 로컬에서 화면만 보기

```bash
python3 -m http.server 8080 --directory docs
# http://localhost:8080
```

`API_BASE` 가 배포 URL을 가리키므로 실데이터에 붙습니다. 화면만 만지려면 배포 전 URL 그대로 두면
"서버 주소가 설정되지 않았습니다" 안내가 뜹니다.

## 7. clasp (선택)

로컬에서 GAS를 직접 밀어 넣고 싶다면:

```bash
npm i -g @google/clasp
clasp login
cd gas
cp .clasp.json.example .clasp.json   # scriptId 를 채운 뒤
clasp push
```

`scriptId` 는 Apps Script 편집기 → 프로젝트 설정 → 스크립트 ID 에서 확인합니다.
