# 시트 스키마 (확정본 v2)

스프레드시트 1개 안의 **탭(시트) 10개**로 구성합니다. 실제 생성은 손으로 하지 말고
`gas/Setup.gs` 의 `setupSpreadsheet()` 를 한 번 실행하면 헤더·서식·데이터 검증·시드까지 만들어집니다.

> **v2 변경점** — 행정팀 마스터시트 초안을 반영했습니다.
> `캠프 대상`(청년부/장년부)과 `참여 일자`(10/31·11/07)는 **서로 독립적**입니다.
> 청년부인데 11/07에 참여하는 인원이 실제로 있어, 이 둘을 한 컬럼으로 합치면 안 됩니다.
> 앱의 모든 "회차" 구분은 **참여 일자**를 기준으로 합니다(타임라인, 갤러리 공개 범위, 조 구분).

## 공통 규칙

- **1행이 헤더**이고, 코드는 **헤더 텍스트로 컬럼을 찾습니다**. 열 순서를 바꿔도 동작합니다.
  단, **헤더 이름을 바꾸면 깨집니다.** 이름 변경이 필요하면 `gas/Sheets.gs` 의 `COL` / `SCHEMA` 를 같이 고치세요.
- 행정가가 열을 **추가**하는 것은 자유입니다(코드가 무시합니다). 삭제만 하지 마세요.
- ID 컬럼은 코드가 생성합니다. 손으로 채우지 마세요.
- 날짜/시각 기록은 `Asia/Seoul` 기준 ISO 문자열(`2026-10-31T14:05:00+09:00`)로 저장됩니다.
- **조를 특정하는 키는 `(참여 일자, 조 배정)` 조합**입니다. 10/31의 "1조"와 11/07의 "1조"는 다른 조입니다.

## 1. `마스터` — 참가자 명단 (원장)

`참가자ID` 와 `등록일시` 두 열만 코드가 추가로 씁니다.

### 교역자·스태프 — 조 없이 (v16, D-051)

"운영진" 조를 만들지 **않습니다**. 가짜 조는 진행 보드·명단 점검·조 목록·회비 보드에 새어 나갑니다.

| 사람 | `역할` | `조 배정` | `담당 지점` | `참여 일자` | 앱 |
|---|---|---|---|---|---|
| 거점 스태프 | `스태프` | 비움 | `CP1`~`CP4` | 비우면 전 회차 | **내 지점** — 그 지점에 오는 모든 조 기록·점수 |
| 순회 스태프 | `스태프` | 비움 | 비움 | 비우면 전 회차 | **진행** — 읽기 전용 |
| 교역자 | `교역자` | 비움 | — | 비우면 전 회차 | **진행** — 읽기 전용. 관리 기능은 운영 콘솔(PIN) |
| 캠티(조장) | `조장` | `1조` | — | 필수 | 지금 그대로 |

- **참여 일자 공란 = 전 회차.** 한 사람은 한 행으로 둡니다. 로그인하면 오늘 날짜의 회차
  (없으면 다음, 다 지났으면 마지막) 로 들어갑니다. 한 회차만 일하면 그 날짜를 적습니다.
- 조가 **있는** 스태프·교역자는 예전처럼 그 조의 조장 권한입니다(담당 지점이 있으면 지점이 우선).
- 회차마다 한 행씩 두면(이름·번호 같은 두 행) 캠프 당일에는 그날 행으로 들어가지만,
  그 밖의 날에는 로그인이 막힙니다 — 명단 점검이 알려 줍니다.

### 이름 뒤 4자리 표기

마스터시트는 동명이인을 구분하려고 이름 뒤에 숫자 4자리를 붙여 씁니다(`이승천7377`).
참가자에게 "이승천7377"을 입력하라고 할 수는 없으므로, **이름**은 `이승천`(구분번호 뗀 것)과
`이승천7377`(그대로)을 모두 받습니다. 화면 표시에서는 구분번호가 자동으로 제거됩니다.

### 뒷 4자리 — 연락처를 채우면 스위치를 내리세요

`Config.LOGIN_ALLOW_NAME_DIGITS` 가 인증 수단을 정합니다.

| 시기 | 값 | 인정되는 뒷 4자리 |
|---|---|---|
| 연락처가 임시값인 동안 | `TRUE` (기본) | 연락처 마지막 4자리 **또는** 이름 뒤 4자리 |
| 실제 연락처를 다 채운 뒤 | `FALSE` | 연락처 마지막 4자리 **만** |

⚠️ **`TRUE` 는 임시 조치입니다.** 이름 뒤 4자리는 명단을 본 사람이면 알 수 있어,
켜 둔 채로는 사실상 이름만으로 로그인되는 것과 같습니다.
메뉴 → **명단 점검**이 임시 연락처(같은 번호가 3행 이상 반복)를 감지해,
전부 실제 값이 되면 스위치를 내리라고 알려 줍니다.

### 로그인이 안 되는 경우

`checkDuplicates()`(메뉴 → 명단 점검)가 미리 잡아 줍니다.

- `참여 일자` 가 비어 있음 → 로그인 시 "참여 일자가 아직 배정되지 않았습니다" 안내
- `이름(구분번호 뗀 것) + 뒷4자리` 가 겹치는 사람이 둘 이상 → 참여 일자로 좁혀지지 않으면 `AMBIGUOUS`
- `참가자ID` 가 비어 있음 → "참가자ID 채우기" 실행 필요

## 2. `Teams` — 조 메타 (선택)

조 편성 자체는 `Participants.조 배정` 이 원본입니다. 이 시트는 **표시용 부가 정보**만 담습니다.
비워 둬도 앱은 정상 동작합니다(조 이름은 `1조` 처럼 그대로 표시됨).
메뉴 → "조 목록 동기화" 를 실행하면 명단에 있는 조가 자동으로 채워집니다.

| 헤더 | 예시 | 설명 |
|---|---|---|
| `참여 일자` | `10/31(토)` | `조 배정` 과 함께 조를 특정 |
| `조 배정` | `1조` | |
| `조이름` | `1조 배재` | 화면 표시명. 비우면 `조 배정` 값을 씀 |
| `색상` | `#984534` | 카드 좌측 띠 색 |
| `집결장소` | `PL교회 본당 앞` | |
| `비고` | | |

> 조장은 `Teams` 가 아니라 `Participants.역할 = 조장` 으로 판정합니다.
> 조가 있는 `스태프` / `교역자` 도 조장과 같은 기록 권한을 갖습니다(현장에서 대신 기록해야 할 때가 있어서).

## 3. `Courses` — 배정 코스

조마다 시작 지점을 달리해 현장 혼잡을 분산합니다(기획안 리스크 대응).

| 코스명 | 방문 순서 |
|---|---|
| `A코스(배재 시작)` | `CP1,CP2,CP3,CP4` |
| `B코스(러시아 시작)` | `CP2,CP3,CP4,CP1` |
| `C코스(보구여관 시작)` | `CP3,CP4,CP1,CP2` |
| `D코스(이화여고 시작)` | `CP4,CP1,CP2,CP3` |

`Participants.배정 코스` 와 `코스명` 이 정확히 같으면 매칭되고,
다르더라도 **앞글자(A/B/C/D)** 가 같으면 매칭됩니다. 둘 다 실패하면 `Checkpoints.기본순번` 순서로 되돌아갑니다.

**이 탭은 시드되지 않습니다** — 처음에는 헤더만 있고 비어 있습니다. 그래서 공지를 넣기
전에는 홈 화면에 공지 카드가 아예 뜨지 않습니다(없으면 숨깁니다).

**운영콘솔 `공지` 탭에서 쓰고 고치고 지울 수 있습니다** (D-048). 예약 게시(`게시일시` 를
미래로)는 시트에서만 겁니다 — 콘솔은 만들 때 지금으로 찍고, 수정할 때 그 값을 건드리지
않습니다.

🔴 `Config` 의 **`NOTICE_TICKER`** 와 헷갈리지 마세요. 그쪽은 앱바 바로 아래 **한 줄 띠**고,
홈의 공지 **카드**는 이 탭에서 옵니다. 대상이 `전체` 가 아니면 그 참여 일자·캠프 대상
참가자에게만 보입니다.

## 8. `Timeline` — 당일 타임라인

| 헤더 | 예시 |
|---|---|
| `참여 일자` | `10/31(토)` |
| `순번` | `1` |
| `시작` / `종료` | `09:30` / `09:50` |
| `내용` | `도착 · 등록 · 조편성 확인` |
| `장소` | `PL교회` |
| `비고` | `명찰/조 배정표 배부` |

시드는 기획안대로 **10/31 은 교육(09:30)부터**, **11/07 은 오후 답사(13:00)부터** 로 들어갑니다.
답사 구간은 조마다 순서가 달라 "① 첫 번째 지점" 처럼 중립적으로 적혀 있습니다 —
실제 지점명은 앱의 "코스" 화면이 조별로 보여 줍니다.

## 9. `Config` — 운영 설정

| 헤더 | 설명 |
|---|---|
| `키` / `값` / `설명` | `설명` 은 사람이 읽는 메모. 코드는 안 씀 |

배포 없이 바꿀 수 있고 **즉시 반영**됩니다. 속도를 위해 5분 캐시에 담지만
시트를 고치는 순간 캐시가 자동으로 비워집니다(`onEdit`, D-022).

예외는 **사람이 직접 친 편집이 아닌 변화**(`IMPORTRANGE` 갱신, 수식 재계산, 외부 API)뿐입니다.
그때만 메뉴 → `캐시 비우기 (설정·공지·일정)` 를 누르세요.

> **`SESSION_1`/`SESSION_2`/… 를 여기서 고치면 다섯 탭이 자동으로 따라옵니다.**
> 회차 라벨은 명단·조·일정표·진행·일지에 함께 박혀 있어 Config 만 바뀌면 조가 끊어지므로,
> `onEdit` 이 나머지를 함께 바꿔 줍니다 (D-021).
>
> 🔴 **2차(`SESSION_2`)를 먼저 바꾸세요.** 새 1차 라벨이 옛 2차 라벨과 같으면
> 두 회차가 섞입니다. 그런 경우 **값을 되돌리고 순서를 안내**합니다.
> 한 번에 처리하려면 시트 메뉴 **`일정 변경 (회차 날짜)`** 을 쓰세요.

> **회차를 늘릴 때는 시트 메뉴 `회차 추가 (사전답사 등)` 를 쓰세요.**
> Config 에 두 줄을 손으로 적어도 앱은 읽지만, **`참여 일자` 드롭다운이 안 따라와**
> 명단에서 새 회차를 고를 수가 없습니다. 메뉴는 Config 기록 · 일정표 복사 ·
> 드롭다운 갱신 · 캐시 비우기를 한 번에 합니다.

> **`ADMIN_PIN` 과 `TOKEN_SECRET` 은 이 표에 없습니다.** 시트가 아니라 Apps Script 의
> **스크립트 속성**에 있습니다. 시트를 복사해도 따라가지 않습니다 (D-020).

| 키 | 기본값 | 의미 |
|---|---|---|
| `CAMP_NAME` | `정동, 신앙탐험대` | 앱 상단 타이틀 |
| `CAMP_SUBTITLE` | `PLC 성경적세계관 캠프` | 부제 |
| `SESSION_1` | `10/31(토)` | 1차 참여 일자 — **명단 표기와 글자까지 같아야 함** |
| `SESSION_1_DATE` | `2026-10-31` | 1차 실제 날짜 |
| `SESSION_2` | `11/07(토)` | 2차 참여 일자 |
| `SESSION_2_DATE` | `2026-11-07` | 2차 실제 날짜 |
| `SESSION_3` … | *(없음)* | **회차는 2개로 정해져 있지 않습니다.** `SESSION_<숫자>` 를 더 얹으면 일정표·조·명단 점검·관리자 필터가 따라옵니다 (D-026) |
| `SESSION_n_ACTIVE` | `TRUE` | 🔴 **`FALSE` 면 그 회차 참가자는 로그인할 수 없습니다.** 명단은 그대로 남습니다. 사전답사가 끝나면 이걸로 끕니다 (D-031). 키가 없으면 활성으로 봅니다 |
| `GALLERY_SCOPE` | `ALL` | 탐험일지 공개 범위. `ALL`=같은 참여 일자 전체, `TEAM`=같은 조, `SELF`=본인만 |
| `JOURNAL_REQUIRE_APPROVAL` | `TRUE` | `TRUE`면 승인된 일지만 갤러리에 노출 |
| `JOURNAL_OPEN` | `TRUE` | `FALSE`면 일지 작성·수정 차단 |
| `PROGRESS_OPEN` | `TRUE` | `FALSE`면 조장의 지점 체크 차단 |
| `SHOW_FEE` | `TRUE` | 회비 상태 화면 노출 여부 |
| `DRIVE_FOLDER_ID` | (비움) | ⚠ 탐험일지 사진 저장 폴더 ID. 반드시 입력 |
| `TOKEN_TTL_HOURS` | `12` | 로그인 유지 시간 |
| `LOGIN_ALLOW_NAME_DIGITS` | `TRUE` | ⚠ 이름 뒤 4자리로도 로그인 허용. **연락처를 다 채우면 `FALSE`** |
| `PHOTO_MAX_BYTES` | `4000000` | 업로드 사진 1장 최대 크기 |
| `NOTICE_TICKER` | (비움) | 앱 상단 한 줄 공지. 비우면 숨김 |

> **관리자 PIN 은 시트가 아니라 스크립트 속성(`ADMIN_PIN`)에 둡니다.**
> 시트에 두면 편집 권한이 있는 사람 전원에게 노출되기 때문입니다.

## 행정팀 탭 동기화 (`MasterSync.gs`)

행정팀이 쓰던 탭 간 동기화 스크립트를 같은 프로젝트에 넣었습니다. 동작은 그대로입니다.

- 다른 탭에서 `이름` 을 입력하면 `마스터` 의 해당 행을 끌어와 채웁니다.
- 어떤 탭에서 값을 고치면 같은 `이름` 을 가진 다른 탭의 같은 헤더 칸도 따라 바뀝니다.
- `성별` · `나이` · `연락처` 는 탭마다 따로 관리하므로 동기화하지 않습니다.
- 메뉴 `🔄 동기화 관리 → 헤더 일치 여부 검사` 로 마스터에 없는 헤더를 빨갛게 표시합니다.

앱과 한 프로젝트에서 돌리려고 세 가지를 조정했습니다.

| 문제 | 조정 |
|---|---|
| `onOpen` 이 두 파일에 있으면 **하나만 살아남아** 다른 메뉴가 조용히 사라짐 | `onOpen` 은 `Setup.gs` 한 곳에만 두고, 동기화 메뉴는 `addMasterSyncMenu_()` 로 붙임 |
| 헤더 검증이 앱 시트(`Config`·`Journal`·`Progress`…)를 전부 빨갛게 칠함 | 앱이 관리하는 탭은 동기화·검증 대상에서 제외 |
| 원장 탭 이름이 `마스터` 인데 앱은 `Participants` 를 찾음 | `resolveSheetName_()` 로 양쪽 모두 같은 탭을 가리키게 함 |

> `onEdit` 같은 단순 트리거는 **사람이 시트를 편집할 때만** 실행됩니다.
> 앱(웹앱)이 시트에 쓰는 값에는 반응하지 않으므로 동기화 무한루프는 생기지 않습니다.

## 초기 세팅 순서

1. Google Sheets 새 문서 생성 → 확장 프로그램 → Apps Script.
2. `gas/` 의 파일들을 붙여넣고 저장.
3. 편집기에서 `setupSpreadsheet()` 실행 → 10개 탭 + 헤더 + 시드 데이터 생성.
4. 프로젝트 설정 → 스크립트 속성에 `ADMIN_PIN`(6자리 이상) 추가.
   - `TOKEN_SECRET` 은 없으면 자동 생성됩니다.
5. `Config` 의 `DRIVE_FOLDER_ID` 와 `SESSION_1` / `SESSION_2` 확인.
6. **행정팀 명단을 `마스터` 탭에 붙여넣기** — 헤더가 같으므로 값만 그대로 붙이면 됩니다.
   (템플릿: `docs-dev/spec/participants-template.csv`)
7. 스프레드시트 메뉴 `🧭 캠프 앱` 에서 차례로 실행
   - **참가자ID 채우기**
   - **조 목록 동기화**
   - **명단 점검** → 나온 경고를 모두 해소
8. 배포 → 새 배포 → 웹 앱 / 실행 계정 `나` / 액세스 `모든 사용자` → `/exec` URL 복사.
9. `docs/assets/js/config.js` 의 `API_BASE` 에 붙여넣고 push.
